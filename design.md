# RedRouter interface contract

## Product job

RedRouter is a technical workbench for getting a local AI router operational and keeping it observable. The primary journey is: connect a provider, create a client key, copy the endpoint configuration, validate, then monitor usage.

## Hallmark direction

- Genre: modern-minimal.
- Macrostructure: Workbench.
- Tone: technical, direct, utilitarian.
- Density: compact, with progressive disclosure for advanced networking and administration.
- Enrichment: none. Product state and executable configuration are the content.

## Locked system

- Use the vendored RedDB tokens in `vendor/ds`; do not duplicate or improvise color values.
- Space Grotesk is the interface face. JetBrains Mono is reserved for endpoints, keys, commands, identifiers and compact metadata.
- Red is for primary action, current selection and meaningful status—not decoration.
- Preserve light and dark schemes.
- Prefer flat operational lists, dividers and status rows over nested cards or equal marketing grids.
- Keep existing routes and behavior. Reveal complexity only where the task requires it.

## Interaction contract

- Every control has visible default, hover, `focus-visible`, active, disabled, loading, error and success treatment where applicable.
- Interactive targets are at least 44 CSS pixels.
- Dialogs use the native dialog model, trap focus, close with Escape, restore focus and carry an accessible name.
- Actions remain discoverable without hover. Motion communicates state only and respects reduced-motion.
- At 320, 375, 414 and 768 px: no horizontal page scroll, clickable labels stay on one line, and multi-column step headers collapse.

## Anti-slop exclusions

No fake traffic lights or browser chrome, glass panels, decorative gradients, invented metrics, italic display headings, gratuitous imagery, card-in-card composition, pervasive `transition-all`, or literal colors that bypass the token system.
