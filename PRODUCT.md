# Product

## Register

product

## Users

Developers and operators who run RedRouter locally or on a trusted network. They need to connect provider accounts, create client credentials, copy a compatible endpoint configuration, validate that traffic can flow, and monitor routing without learning the router's internal architecture first.

## Product Purpose

RedRouter provides one local, OpenAI-compatible gateway across many AI providers. The dashboard succeeds when a user can move from an unconfigured install to a validated client connection quickly, then diagnose provider, routing, quota, and usage state without leaving the product.

## Brand Personality

Technical, direct, dependable. The interface should feel like a mature operator tool: concise enough for experts, explicit enough for first-time setup, and calm when presenting failures or sensitive configuration.

## Anti-references

Avoid generic AI dashboards, decorative command centers, marketing-card grids, glass panels, fake telemetry, neon-on-black terminal cosplay, and interfaces that make ordinary provider setup feel novel or mysterious. Do not bury core setup behind hover states or expose advanced networking before it is needed.

## Design Principles

1. Lead with the next executable task, not a product tour.
2. Make system state and recovery paths explicit.
3. Reveal operational complexity progressively.
4. Use familiar controls and consistent vocabulary so the tool disappears into the workflow.
5. Treat configuration, endpoints, and real runtime state as the visual content.

## Accessibility & Inclusion

Target WCAG 2.2 AA for the dashboard. Support keyboard-only operation, visible focus, named dialogs and controls, sufficient contrast, non-color status cues, reduced motion, and layouts without horizontal page scrolling from 320 CSS pixels upward.
