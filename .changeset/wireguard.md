WireGuard, both directions. Private access (API Endpoint → Tunnels → Private): RedRouter generates the server keys and the server config, adds peers and hands each peer's config out exactly once (the peer private key is never stored), and shows whether the interface is up; you bring it up on the host with `wg-quick`, so RedRouter needs no root. Peers get a split tunnel (only the RedRouter address travels through the VPN) and a preshared key; the status warns when RedRouter is bound to loopback and names the flag that exposes it. VPN egress (Settings → Proxies): paste a WireGuard config (Mullvad, Proton, WARP, your own) and RedRouter runs `wireproxy` in user space as a local, password-protected SOCKS5 proxy registered in the proxy registry, so provider traffic can leave through the VPN; assignments fail closed when the tunnel is down. The wireproxy download is refused until its SHA-256 checksums are pinned in `src/lib/wireguard/egressBinary.ts`; until then install wireproxy yourself and RedRouter finds it on PATH. Both are local-only, management-authenticated and audited, and neither WireGuard prefix can be whitelisted for the manage-scope bypass. Nothing was tested against a live interface or VPN.
