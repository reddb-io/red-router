Every provider is now opt-in; nothing comes configured or pre-approved. A provider is enabled only when you added an active connection to it or, for the sources that work without one (AI Horde, Veo AI Free, UncloseAI, DuckDuckGo, OpenCode/Zen/Go anonymous access, Kilo Code and Pollinations anonymous access, Context7 and the local CLI bridges), you explicitly enabled it. Until then such a source has no credentials: it is absent from `/v1/models`, the dashboard Models page, the combo builder and the `auto/*` combos, and it can no longer be picked by routing or by the keyless DuckDuckGo search fallback. `GET /api/providers` now returns `providerAvailability` per provider (`connected`, `free-optin` or `available`), and `GET/POST /api/providers/free-sources` lists the free sources and enables or disables them one at a time or all at once (the four local CLI bridges always stay individually opt-in). Behaviour change for existing installs: a free source you used without a connection stops working until you enable it; the same endpoint reports which ones had successful traffic in the last 90 days (`legacyUsage`) so you can re-enable them in one call. Providers that have a connection, `blockedProviders` and your environment-variable API keys behave as before. The providers page will show this in a later release.
